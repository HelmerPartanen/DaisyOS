# Gaming validation — 2026-10-15

## Implemented

- Bottom panel and edge sensor use the Wayland overlay layer, above fullscreen clients.
- Auto-hidden taskbar and system bar can reveal and hide independently during fullscreen. Repeated compositor snapshots preserve an active reveal. Hidden chrome passes input through, including when fullscreen temporarily hides a normally visible bar.
- Removed the fullscreen bottom scrim so an elevated panel does not paint a strip across the game.
- Gaming Mode registers detected Steam/Lutris launchers and descendants with GameMode. Discovery and native registration/cleanup run outside the input thread. Refreshes do not wait for UI policy callbacks, and transient refresh failures are logged and retried.
- The system-wide GameMode helper uses `setpriv --pdeathsig TERM` so forced shell replacement does not leave a permanent `sleep infinity` request.
- `scripts/configure-gaming.sh` checks or explicitly provisions the selected desktop user's access through the installed GameMode group policy.

## Performance findings and limits

The live system has an Intel Core i7-3770K, Quadro RTX 4000, and a 2560×1440 output configured at approximately 180 Hz. Both KWin and CS2 loaded the NVIDIA graphics stack. In one active-game sample the GPU reached P0, 1800 MHz graphics and 6500 MHz memory clocks, drawing approximately 88 W. A CPU core thermal-throttle counter read zero.

CS2's existing HUD displayed 140–194 FPS in some warmed local-map/spectator views. Those views differ from the originally reported scene; they are not a before/after benchmark or evidence of a particular percentage improvement. Startup showed large frame-time spikes. Some measurements overlapped compilation and are not clean gameplay benchmarks.

Both the workspace and the installed game reside on `/dev/sdb2`, a rotational Hitachi drive. During startup the kernel reported substantial I/O stalls, with recent `some` pressure samples around 40–60%. This is evidence of a startup/storage constraint, not proof that storage explains every low-FPS scene. CPU utilization averaged across all logical CPUs cannot exclude a busy game thread.

The GameMode journal recorded authorization failures for `cpugovctl set performance`; the live governor remained `schedutil`. The desktop user is missing the installed `gamemode` group. The following step is prepared but **not applied**, because this session has no passwordless sudo:

```sh
sudo scripts/configure-gaming.sh --user "$USER"
```

Sign out and back in afterward, then verify the installed daemon with `gamemoded -t`. GameMode installation or an active request alone must not be presented as proof that privileged tuning succeeded. No global driver overrides, overclocks, permanent governor changes, or package installations were applied.

The originally reported transient global hover failure was not conclusively isolated. Hover and clicks worked after the shell replacement in both native Wayland and XWayland fullscreen probes, and hover tooltips worked above CS2 itself. These observations do not prove the transient can never recur.
