# Desktop experience review — 2026-11-02

This delivery implements the floating launcher and confirmed Files/clipboard recovery issues. The review uses source inspection, headless input, and rendered component frames. It does **not** certify a complete physical desktop walkthrough. The running native desktop and its Release binaries were left untouched; no ISO was built.

## Confirmed findings and changes

| User action / reproduction | Impact | Delivered behavior | Acceptance evidence |
| --- | --- | --- | --- |
| Open Launcher with Super or the taskbar | Fullscreen material hides the user's working context | Centered 900 × 600 maximum panel, 24px outer clearance, themed double edge and bounded blur | LauncherPanelTests; GuiMotionTests blur-region assertions; light/dark frames |
| Resize while a later app is selected | Selected tile can fall outside the current page | Recalculate the visible page from the selection; retain the page's first app as the anchor when no selection exists | LauncherPanelTests resize regression |
| Browse hundreds of applications | Every page receives a footer indicator, crowding panel utilities | At most seven indicators around the current page, with exact page labels and tooltips | 2,000-app indicator regression |
| Reopen Launcher during dismissal | Risk of stale exit completion or discontinuous animation | Existing interruptible reveal retained; use shared 220/140ms shell tokens; stationary panel geometry | GuiMotionTests; LauncherPagingTests |
| Click panel padding or empty grid space | Pointer focus can leave search or accidentally dismiss the panel | Entire panel counts as inside; outer overlay remains a dismissal target | Panel hit-boundary and existing empty-space focus checks |
| Copy text with leading spaces or a trailing newline, then retrieve history | History silently changes the copied content | Retain exact text; preview formatting stays separate | ClipboardPolishTests |
| Click directly on a clipboard pin/delete icon | Child-icon events can also activate the parent card, copy, and close history | Exclude nested action buttons and non-left clicks from card activation | Headless pointer clicks on actual child icons |
| Search clipboard history, then press Escape | Closing immediately loses the current search context | First Escape clears search; second closes; distinguish no matches from empty history | ClipboardPolishTests |
| Use keyboard to retrieve a clipboard item | Cards were pointer-only | Focusable cards, Enter/Space activation, shared focus ring, named actions, copy failures retain the window | Keyboard activation and exact-text copy regression; pointer/search checks |
| Open a missing folder, restore it, then refresh | F5/Ctrl+R does nothing after initial load failure | Refresh retries the failed location without adding history or clearing the filter | FilesPolishTests retry regression |

The launcher keeps existing tile dimensions, page recycling, search ranking, activation, menu hosting, swipe physics, pinch handling, and asynchronous icons. Page size follows the available viewport. Its native window remains a transparent outside-dismissal/input host; only the bounded material frame contributes launcher blur. Popup coordinates still use the full overlay coordinate system.

The calendar month/year control also now uses the same compact button class as its neighboring navigation actions. The existing calendar sizing check passes. A notification pointer test was corrected to click the rendered body instead of a fixed coordinate outside the content; its open/dismiss assertions remain intact.

## Unresolved confirmed gap

Clipboard history has no collection producer in the current source: `ClipboardHistoryService.AddClip` has no production call sites. The card/search/copy fixes above operate on seeded history; they do not make ordinary copies populate history. System-wide collection requires Wayland clipboard/data-control integration and explicit handling of session lock and clipboard ownership. Do not describe this delivery as end-to-end clipboard history support. This is a high-priority follow-up.

## Fresh launcher measurements

Both measurements use the same Release harness, 2,000 synthetic applications, 1280 × 900 logical output, five warmups and 40 measured samples. Animation durations are disabled. The baseline is the pre-existing Release assembly (`a8a42c95…`), copied into a separate harness; the candidate is built from this working tree into a temporary output directory. Baseline source provenance was not independently rebuilt. Both assembly hashes are recorded in the raw reports.

| CPU preparation and render operation | Baseline median / p95 (ms) | Candidate median / p95 (ms) | Baseline / candidate median allocated bytes |
| --- | --- | --- | --- |
| Search | 63.7 / 85.4 | 41.1 / 55.0 | 1,957,584 / 720,480 |
| Page change | 37.0 / 50.9 | 31.6 / 35.8 | 401,808 / 246,208 |
| Swipe sequence | 127.6 / 161.1 | 106.0 / 113.4 | 761,400 / 463,096 |
| Warm opening | 53.3 / 68.3 | 51.1 / 60.0 | 533,080 / 313,160 |

The fullscreen baseline realizes 32 tiles; the panel realizes 18. Reduced visible work contributes to these numbers, so they do not establish an algorithmic optimization. Single cold samples were 1,489ms and 1,208ms and are not a reliable cold-start comparison. These results measure neither native input-to-display latency nor animation FPS. Raw reports: `artifacts/ux-polish-2026-11-02/benchmark-baseline.json` and `benchmark-after.json`.
