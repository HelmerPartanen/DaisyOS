# DaisyUI

Shared Slint components live in `lib.slint` and `components/`. The Rust crate
supplies runtime appearance mapping; it does not reimplement Slint layout or
rendering. Both migrated apps import the same component definitions.

| Component | API / behavior | Existing reference |
| --- | --- | --- |
| DaisyButton | text/icon, primary/quiet/selected/disabled, radius/type, click, keyboard and focus; `contrast-content` selects the calculator/action contrast role rather than primary-button white labels | ComponentStyles, CalculatorView |
| DaisyLabel | semantic foreground, family and body type by default | ComponentStyles, DaisyTheme |
| DaisyCard | raised fill, surface radius and border | ComponentStyles |
| DaisyGlassPanel | translucent fill/border only; platform requests compositor blur | DaisyTheme, KWinBlur |
| DaisySeparator | stroke role | shared styles |
| DaisySwitch | checked two-way binding/callback, pointer/Space, focus and switch accessibility, 56×24 track, 28×20 thumb, 24px travel, 100ms/reduced motion | ToggleSwitchTheme |
| DaisyTextInput | text two-way binding/edited callback, placeholder, enabled/focus, themed selection and 40px standard input height | PlainTextInputStyles, DaisyTheme |

Primitive geometry literals retained from control templates (such as switch
insets/corner arcs and the 18px calculator glyph) are structural source values,
not newly invented design tokens. Palette, sizes, type, common radii, spaces and
durations come from generated resources.

Regenerate resources with `scripts/generate-slint-tokens.py`; `--check` rejects
drift. Runtime accent derivation follows the existing `App.axaml.cs` algorithm,
including distinct primary/action foreground roles. `apply_theme!` bridges the
per-app global types generated by Slint without duplicating mapping code.
Preferences are read-only. The file observer performs IO/calculation off the UI
thread and posts updates with `upgrade_in_event_loop`.

Selection controls, sliders, scrollbars, dropdowns, navigation, popovers/dialogs,
tooltips and custom motion/virtualized controls remain in the existing UI until
ported and tested. The gallery's Flickable is Slint's built-in scrolling
container; it is not yet the full DaisyOS scrollbar/gesture contract.
